# ADR 0008: Swappable authentication layer (until the director chooses an identity provider)

- Status: Accepted. Director decision 2026-10-17 (Q1): **local login for now**. The dev provider below
  is the login for the MVP. Choosing a real provider (ticket CP-44) is deferred to Phase 2 and must
  happen before any non-local deployment.
- Date: 2026-10-17
- Related: ADR 0003, docs/threat-model.md, ticket CP-12 and CP-44

## Decision in one line

We build one small "who is calling?" plug point now. Every request must pass through it and come out
with a **tenant id, a user id and a list of roles**, or it is refused. For local development a clearly
marked fake login is used that **refuses to start outside local mode**. When the director picks a real
login provider, only this plug point changes.

## Context

- The director has deferred the choice of identity provider (for example Auth0, Okta, Entra ID,
  Keycloak, Clerk, or our own).
- Every other ticket needs a tenant and role to enforce tenancy and permissions.
- Security rules: deny by default; every endpoint has an authorization test including a cross-tenant
  attempt.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| Wait for the decision before building anything | No rework | Blocks almost every ticket |
| Pick a provider now | Real auth sooner | Overrides a director decision |
| **Interface + local-only dev provider** (chosen) | Unblocks all work; swap later | Must make sure the dev provider can never run in staging/production |

## Decision

1. **Interface**: `AuthProvider.authenticate(request) -> AuthContext(tenant_id, user_id, roles)`;
   selected by `CP_AUTH_PROVIDER`.
2. **Dev provider** (`dev`): reads a locally signed JWT (HS256, key from `CP_AUTH_DEV_SIGNING_KEY`,
   **15-minute** expiry) generated by `make dev-token TENANT=... ROLES=...`. The API refuses to start if
   `CP_AUTH_PROVIDER=dev` and `CP_ENV` is not `local` or `test`.
3. **Roles** (approved by the director, Q5): `viewer`, `requester`, `approver`, `admin`,
   `ingestor` (machine identity for telemetry senders). Approvers act for their whole tenant; nobody may
   approve their own request. Permission matrix is in the spec.
4. **Deny by default**: a plugin installs a global dependency; a route is public only if it is in an
   explicit allow-list (`/healthz`, `/readyz`). Test: `test_every_route_requires_auth_unless_public`.
5. **Workers** do not authenticate users; they trust `tenant_id` only from queue messages written by
   the API or outbox, never from external input.

## Consequences

- Good: no ticket is blocked; swapping providers is a single-ticket change (CP-44).
- Risk: a misconfigured environment could run the dev provider; mitigated by the start-up refusal and
  a test for it (`test_dev_auth_refuses_non_local_env`).
